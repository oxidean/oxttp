## 1. Invocation model

- `xh [OPTIONS] <[METHOD] URL> [REQUEST_ITEM]...` (`src/cli.rs` ~L440–485, README L72–122).
- Parser: clap 4 derive, `args_override_self = true` (later flags override earlier ones — applies to `--no-*` too), `disable_help_flag = true` (custom `--help`), styled help output (`STYLES`, `src/cli.rs` L27–35).
- `-V, --version` is auto-generated by clap (`#[clap(version, long_version)]`); `--version` prints version + feature string `xh 0.26.3\n+native-tls +rustls`.
- `xh help` (positional literal `"help"` in the METHOD/URL slot) prints the LONG help and exits 0 (`src/cli.rs` ~L535–545). `--help` prints SHORT help (`ArgAction::HelpShort`, `src/cli.rs` L427–428).
- Binary name detection (`src/cli.rs` ~L576–585, tests ~L1626+):
  - invoked as `xhs`, `xhttps`, or `https` -> `https = true` (default scheme https). `assets/xhs` is a symlink to `xh`.
  - invoked as `http` or `https`, or env `XH_HTTPIE_COMPAT_MODE` set -> `httpie_compat_mode = true` (see section 13).
  - bin name computed from argv[0] minus any `.extension` (e.g. `xhs.exe` -> `xhs`).
- Default options file: `$XH_CONFIG_DIR/config.json` -> JSON `{ "default_options": ["--flag", ...] }` prepended to argv before parsing (`src/cli.rs` `default_cli_args()` ~L735–770). Unreadable/unparseable -> warning `xh: warning: Unable to read|parse config file: ...` to stderr, continue.

## 2. Positional grammar: `[METHOD] URL [REQUEST_ITEM...]`

- `raw_method_or_url` is a REQUIRED positional (`src/cli.rs` L440, `required = true`), except when `--generate` is passed (conflict declared L424).
- Method detection (`parse_method`, `src/cli.rs` ~L773–784): first positional is a method iff **all chars ASCII alphabetic** and non-empty. It is uppercased and parsed as an HTTP method token (any alphabetic word is accepted, e.g. `purge` -> `PURGE`). Caveat: `localhost` alone is consumed as method -> "Missing <URL>" error.
- If method present, next positional is URL; remaining positionals are REQUEST_ITEMs.
- If method omitted -> method is `None`; effective method chosen by `Body::pick_method()` (`src/request_items.rs` ~L227): **GET if body is empty, else POST**. (`--multipart` counts as non-empty even with no items -> POST.)
- URL construction (`construct_url`, `src/cli.rs` ~L786–810):
  - Default scheme `http://` unless `--default-scheme`, `--https`, or invoked-as-https bin name.
  - Leading `://` stripped and replaced with default scheme — enables `xh https ://example.org` paste-style.
  - Leading `:` -> `localhost` prefix: `:`, `:3000`, `:/path`, `:3000/path`.
  - No `scheme://` matching regex `[a-zA-Z0-9]://.+` -> prepend default scheme.
  - Otherwise parsed as-is (full URL).
- Every REQUEST_ITEM is parsed by `RequestItem::from_str` (`src/request_items.rs` ~L39–135); a bare word without separator -> clap error `Invalid value for '[REQUEST_ITEM]...': "..."`.
- `key=value` body items cannot be mixed with `--raw` (`"Request body (from --raw) and request data (key=value) cannot be mixed."`, `src/cli.rs` ~L672) or with a redirected stdin body (`"...from stdin..."`, `src/main.rs` ~L118–132) — pass `--ignore-stdin` to use stdin for other purposes.

## 3. REQUEST_ITEM operators

Separator scan order (`SEPS`, `src/request_items.rs` L42): `==@`, `=@`, `:=@`, `:@`, `==`, `:=`, `=`, `@`, `:` — first unescaped occurrence of the LONGEST matching separator wins (scan walks left-to-right over chars; at each char position tries each sep in that order).

| Syntax | Variant | Effect |
|---|---|---|
| `key==value` | `UrlParam` | Append query param to URL (`url_with_query`, `src/utils.rs` ~L131) |
| `key==@file` | `UrlParamFromFile` | Query param value read from file (tilde-expanded; full contents, not trimmed) |
| `key=value` | `DataField` | JSON string field (`--json`) or form field (`--form`/`--multipart`) |
| `key=@file` | `DataFieldFromFile` | Field value read from file as string |
| `key:=json` | `JsonField` | Raw JSON literal in body (`numbers:=[1,2,3]`, `enabled:=true`); parse error -> `Invalid value for '[REQUEST_ITEM]...'`. NOT allowed with `--form`/`--multipart` ("JSON values are not supported in Form|multipart fields") |
| `key:=@file` | `JsonFieldFromFile` | JSON value parsed from file contents |
| `key:value` | `HttpHeader` | Header `key: value` |
| `key:` (empty value) | `HttpHeaderToUnset` | Remove a header (including auto-added ones like `user-agent:`) |
| `key:@file` | `HttpHeaderFromFile` | Header value read from file, trimmed |
| `key@file` | `FormFile` | Multipart file upload; auto-switches `--form` to multipart; with `--json` and empty key becomes whole-body-from-file; with `--json` and non-empty key -> error `"Can't use file fields in JSON mode (perhaps you meant --form?)"` |
| `@file` (empty key + `@`) | `FormFile{key:""}` -> `Body::File` | Entire request body = file contents. Content-Type from `;type=` or mime_guess on filename, defaulting to `application/json`. Mutually exclusive with data items and only one file allowed (`"Can't read request from multiple files"`). `;filename=` ignored with a warning |
| `key;` (trailing `;`, no other sep) | `HttpHeader(key, "")` | Header with empty value. NB: implementation is `strip_suffix(';')` — "technically too permissive" per code comment; an escaped `\;` still counts |

File-upload params (`parse_part_params`, `src/request_items.rs` ~L147–180): `key@file;type=MIME;filename=NAME`. Params split on literal `;type=` and `;filename=` scanning from the RIGHT; each param consumed once; leftover `;type=`/`;filename=` stay in the filename value (e.g. `f@x;type=a;type=b` -> file `x;type=a`, type `b`). `;filename=` sets the multipart `filename=` in Content-Disposition; `;type=` sets the part Content-Type.

Escaping (`unescape`, `src/utils.rs` ~L11–37):
- Special chars: `= @ : ; \` (`SPECIAL_CHARS` in `src/request_items.rs` L41; nested-JSON key paths add `[ ]`, `src/nested_json.rs` ~L31).
- `\` + special char -> literal char, in BOTH key and value (`weird\:key=value` -> key `weird:key`).
- `\` + non-special char -> backslash kept literally (`f\o\o=\ba\r` -> key `f\o\o`, value `\ba\r`).
- A `\` prevents the following char from starting a separator (the scanner skips both chars).
- Trailing `\` is literal (`foo=bar\` -> value `bar\`).
- To get a literal separator char in a KEY, escape its first char: `foo\==bar` -> data field `foo=` = `bar`.

Nested-JSON keys (`src/nested_json.rs` header comment + `Token::literal`):
- JSON-path grammar in `key` position: `root [path]*` where path = `[text]` (object key), `[number]` (array index), `[]` (array append). Bare `number` first-token is never an index; `\` before a digit inside brackets forces key-not-index.
- Escapable chars inside paths: `= @ : ; [ ] \`.
- Errors surfaced via `nested_json` (e.g. type mismatch object-vs-array) carry the raw key path.

### 4.8 `--no-*` negation flags (auto-generated)

`Cli::into_app()` (`src/cli.rs` ~L694–728) synthesizes a hidden `--no-<long>` for EVERY non-positional arg: `ArgAction::SetTrue` + `overrides_with(<id>)`. Semantics: **last occurrence wins** — `--x --no-x` = unset; `--no-x --x` = set (differs from HTTPie's order-insensitive negation, documented in code comment). Applies to all 56 declared options, e.g. `--no-check-status`, `--no-stream`, `--no-follow`, `--no-verify`, `--no-proxy` (clears all accumulated proxies), `--no-resolve`, `--no-format-options`, `--no-unstable-m-sig-*`, `--no-help`, etc. `--no-json/--no-form/--no-multipart` revert to default JSON body type.

Two flags have first-class tri-state handling via `matches.get_flag("no-…")`: `--check-status`/`--no-check-status` -> `Option<bool>`; `--stream`/`--no-stream` -> `Option<bool>`.

### 4.9 HTTPie-compat status of flags

- All declared flags are functional; these are functional-but-hidden or feature-gated:
  - `--bearer` — functional but **hidden** (HTTPie has it; xh hides it).
  - `--default-scheme` — functional but **hidden**.
  - `--native-tls` — functional but **hidden** when build lacks both TLS backends.
  - `--unstable-m-sig-*` — **hidden + hard error** without the `http-message-signatures` feature.
- No HTTPie **no-op** flags exist (xh errors on unknown flags; HTTPie flags like `--path-as-is`, `--chunked`, `--cert-key-pass`, `--boundary` are NOT accepted).
- HTTPie compat mode only changes `--check-status` default (section 4.7, `src/main.rs` L724: `args.check_status.unwrap_or(!args.httpie_compat_mode)`).

## 8. Exit codes & error style

`doc/xh.1.md` EXIT STATUS + `error_reporting::exit_code` (`src/error_reporting.rs` ~L64–78) + `run()` (`src/main.rs` ~L725–730):

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | any application error: network errors, body/file errors, incomplete download, invalid --verify/--cert files, etc. |
| 2 | request timeout (`reqwest::Error::is_timeout`) — note: clap's own parse errors also exit 2 via `err.exit()` (clap convention; help/version exit 0) |
| 3 | HTTP 3xx with `--check-status` and no `--follow` |
| 4 | HTTP 4xx with `--check-status` |
| 5 | HTTP 5xx with `--check-status` |
| 6 | `TooManyRedirects` |

Caveat: the man page claims "1: Usage, syntax or network error" but clap parse errors actually exit **2**.

Error output style (`main()` ~L80–96): `{bin_name}: error: {err:?}` (anyhow Debug = message + `\n\nCaused by:\n    <cause>` chain, and with `--debug` full backtrace via alternate `{err:#?}` logged separately). Extra diagnostics from `additional_messages()`: rustls cert expiry "Certificate not valid after <ts> (<dur> ago)." / "not valid before ..."; native-tls min-version "Try running without the --native-tls flag."

Warning style (env_logger, `cli.rs` ~L718–732): `{bin_name}: warning: <msg>` (`error|warning|info|debug|trace` levels). Debug style: `[<t>s LEVEL module] msg` (float seconds).

Warnings catalog (user-visible `log::warn!`s):
- `--continue can't be used with a 'Range:' header. --continue will be disabled.`
- `--compress can't be used with a 'Content-Encoding:' header. --compress will be disabled.`
- `Ignoring ;filename= tag for single-file body. Consider --multipart.`
- `Custom CA bundles with native-tls are broken` / `Client certificates are not supported for native-tls[...]`
- `rustls does not support older TLS versions. native-tls will be enabled. Use --native-tls to silence this warning.` / `...Consider building with the 'native-tls' feature enabled.`
- `Redirect to invalid URL: ...`
- `HTTP <status> <reason>` on check-status failure with redirected output / headers hidden.

## 9. Misc behavioral details for 1:1 parity

- `Accept` header injected when printing request headers if absent (`*/*`); `Host` and `Content-Length` synthesized for display (`printer.rs` ~L360–400).
- Cookie jar always active (in-memory); `Cookie:` request item parsed into jar for session runs.
- `--download` short-circuit: body goes to file, headers printed to stderr (Buffer::stderr when download), filename dedup only when stdout is TTY and no `-o`.
- Response meta (`m`): `Elapsed time: %.5fs` (request + body download) + `Remote address: "<ip:port>"` when available.
- `--print` explicit value disables the default `--verbose`-implied print; `--history-print` defaults to `--print` when absent.
- `--follow` + verbose prints intermediates via `--history-print` format.
- Header display: values decoded latin1 (isomorphic) by default; if value is also valid UTF-8 the UTF-8 form shown as ` (UTF-8: <text>)` annotation (FAQ + `utils.rs` `BadHeaderValue`). Response reason phrase falls back to canonical reason; `<unknown status code>` otherwise.
- `--generate` + any positional -> clap conflict error.
- `format_options` last-wins merge across repeated flags.
- Method tokens: any `[A-Za-z]+` string (uppercased). URLs are NOT validated beyond `url::ParseError`.
- Session naming: `<host>` or `<host>_<port>`; named sessions reject hosts `.`/`..`.

## 10. Feature flags affecting user surface (Cargo.toml L99–109)

- `rustls` (default) / `native-tls`: TLS backend; `--native-tls` hidden unless both.
- `http3`: enables `3-prior-knowledge`; else error.
- `http-message-signatures`: unhides the four `--unstable-m-sig-*` options.
- `network-interface`: enables `--interface` name->IP on non-SO_BINDTODEVICE platforms.
- Build-time `XH_FEATURES` string (`+native-tls +rustls`) embedded in `--version`.
